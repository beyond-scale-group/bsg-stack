## Audit Notes (tooling)

Two script defects in the `security-report` skill were hit while
producing this tick and are recorded here as facts, not remediated
(out of scope for this agent):

1. **`secrets.sh` never applies `.securityignore`.** `collect.sh`
   emits the ignore-file content under the JSON key `securityIgnore`
   (`claude-skills/skills/security-report/scripts/collect.sh:121`),
   but `secrets.sh` reads it back as `.securityignore` (lowercase,
   `claude-skills/skills/security-report/scripts/secrets.sh:26`). The
   key-case mismatch means `securityignore` always resolves to `null`
   in the running script, so the skip-file/skip-pattern lists are
   always empty — `.securityignore` is silently never honored. In this
   repo the practical effect is severe: without the ignore in effect,
   `secrets.sh` re-flags the `AKIAIOSFODNN7EXAMPLE` placeholder inside
   every historical `security/reports/*.md` file that itself recorded
   that finding, and the per-match `jq` append is O(n²) on the growing
   findings array — the unpatched run did not complete within a 2-minute
   timeout. This tick worked around the bug locally (a copy of the
   snapshot with the key duplicated under both cases) to produce the
   results above; no source file under `claude-skills/` was modified.
2. **`generate-report.sh` ignores a `--snapshot` argument.** The script
   has no arg parser and unconditionally calls `collect.sh` itself
   (`claude-skills/skills/security-report/scripts/generate-report.sh:13`),
   so passing `--snapshot <path>` (as `SKILL.md`'s own "reuse one
   snapshot" invocation pattern suggests) is a silent no-op; every
   invocation re-collects and re-runs all three reporters from scratch,
   inheriting bug (1)'s slowdown each time.

Recommend filing these as `tech` issues for a human/tech-lead tick to
pick up — this agent does not self-file or remediate.
