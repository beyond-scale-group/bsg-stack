## Audit Notes (tooling) — escalation on a known defect

The `.securityignore` key-case bug first recorded in the 2026-07-02
audit and repeated in the 2026-07-03 00:46 sweep (PR #706) is still
present and unfixed, and its impact has **worsened** as the repo has
grown:

- `collect.sh` emits the ignore-file content under the JSON key
  `securityIgnore` (`claude-skills/skills/security-report/scripts/collect.sh:121,137`).
- `secrets.sh` reads it back as `.securityignore` (lowercase,
  `claude-skills/skills/security-report/scripts/secrets.sh:46-47`).
  `jq`'s key lookup is case-sensitive, so this is always `null` — the
  skip-file/skip-pattern lists are silently empty and `.securityignore`
  is **never honored** on an unpatched snapshot.
- **New this sweep:** running the unpatched pipeline (`generate-report.sh`,
  which calls `secrets.sh` against a snapshot without the workaround)
  no longer just runs slowly — it now **crashes**, reproduced 3× in a
  row in a clean shell:
  ```
  /Users/gdumas/.claude/skills/security-report/scripts/secrets.sh: line 118: /usr/bin/jq: Argument list too long
  ```
  Root cause: because `.securityignore` isn't applied, the scanner
  also matches the deliberate sample credentials in
  `claude-skills/skills/security-report/references/**` and the
  `security/reports/**` archive (which itself echoes those samples in
  every prior report). At the repo's current size (596 tracked files,
  up from 562 two sweeps ago) the accumulated `findings` array is large
  enough that `secrets.sh:118` — `jq -n --argjson findings "$FINDINGS_JSON" ...`
  passes the entire findings blob as a single command-line argument —
  exceeds the OS `ARG_MAX` limit and `jq` fails to exec. The script
  then produces **no stdout at all**, so an unpatched
  `generate-report.sh` invocation silently yields a zero-byte report
  file rather than a visibly broken one.
- **Workaround used for this report** (no source file modified): a
  snapshot copy with the ignore-file content duplicated under both
  `securityIgnore` and `securityignore` keys, discarded after use.
  With the workaround, `secrets.sh` completes in ~9.4s with 0 findings
  across 574 scanned files (22 correctly excluded) — matching the
  workaround already documented in the previous sweep's report.

**This is now a functional break, not just a performance issue** —
`generate-report.sh` (the single invocation the `security` tick relies
on) fails outright on this repo without a manual workaround, and fails
*silently* (empty file, exit code masked by shell wrapping) rather than
loudly. Filing this as a `tech` issue is recommended; `security` has no
`auto-implements` scope and does not self-file or remediate.
