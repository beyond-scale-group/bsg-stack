### Scanner false-positive note

The secrets scanner reports 6,152 `AKIAIOSFODNN7EXAMPLE` hits, all in paths
already declared in `.securityignore`:

- `security/reports/**` — prior audit reports that echo the placeholder key from reference docs
- `claude-skills/skills/security-report/references/**` — deliberate pattern examples in the skill's own documentation
- `docs/known-false-positives.md` — the file explaining the scanner examples

**Known defect:** `collect.sh` stores the ignore list under the key `securityIgnore`
(camelCase) but `secrets.sh` reads it with `jq -r '.securityignore'` (all-lowercase).
This key name mismatch means `.securityignore` is never applied at scan time — all
false-positive hits from ignored paths appear in every report. The ignore list exists
and is correct; only the script wiring is broken. This is a defect in
`claude-skills/skills/security-report/scripts/` and should be fixed in bsg-stack
(remediation is out of scope for this audit tick).
