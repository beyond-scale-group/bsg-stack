**Note — scanner key-name bug (non-breaking):** `secrets.sh` queries `.securityignore` (lowercase) from the snapshot
but `collect.sh` writes the key as `securityIgnore` (camelCase). The ignore rules are not applied from the snapshot;
they happen to be correct here because all raw findings fall within the known-false-positive paths
(`claude-skills/skills/security-report/references/**`, `security/reports/**`, `docs/known-false-positives.md`).
If a real credential were added outside those paths, the scan would correctly flag it. This is a latent
defect: if a future `.securityignore` entry targets a path *not* in those three prefixes, it would be silently
ignored by the scanner. Filed for remediation separately (not a silence-breaker for this audit).
